# Release process

1. Verify the locked build, tests, lint and documented CLI on supported hosts.
2. Review the source for secrets, private data, upstream licenses and security risks.
3. Publish only demonstrated capabilities and reproducible results; label estimates.
4. Obtain maintainer approval for repository visibility and version tags.
5. Publish a versioned changelog and exact reproduction instructions.

The first public alpha requires no hardware. FPGA claims require routed reports and separately recorded physical evidence. Keep raw private device data outside the repository.
